## What is MCP?

**Model Context Protocol (MCP)** is an open protocol that lets Claude connect to external systems like APIs, databases, and services. Instead of manually writing fetch calls or SQL queries, Claude can directly interact with your WordPress site.

### Benefits of MCP

- **Direct API Access**: Query WordPress REST API without manual fetch calls
- **Database Queries**: Run SQL queries directly on WordPress database
- **Real-Time Data**: Always get current data, not stale snapshots
- **Test Environments**: Spin up InstaWP sites on demand
- **Custom Tools**: Build specialized MCP servers for your workflow

## Exercise 1: Connect WordPress REST API via MCP (30 min)

**Task:** Connect Claude Code to your WordPress site's REST API using MCP transport.

**Context:** MCP allows Claude to directly query your WordPress REST API without manual fetch calls or API clients.

### Requirements

1. Add WordPress REST API as MCP server
2. Test connection with simple queries
3. Fetch posts, pages, and custom post types
4. Query WordPress settings via API
5. Document common API endpoints

### Setup Steps

**Step 1: Verify REST API is accessible**

```bash
# Test your WordPress REST API
curl https://your-site.local/wp-json/wp/v2/posts

# Should return JSON array of posts
```

**Step 2: Add WordPress MCP server**

In your Claude Code session:

```bash
# Add WordPress site as MCP server
claude mcp add --transport http wordpress https://your-site.local/wp-json
```

**Step 3: Test the connection**

Ask Claude:

```
Can you fetch the 10 most recent posts from my WordPress site?
```

Claude will now query the REST API directly!

- ✅ Common endpoints documented

### REST API Endpoints Reference

**Common WordPress REST API endpoints:**

```
GET /wp/v2/posts              - List posts
GET /wp/v2/posts/{id}         - Single post
GET /wp/v2/pages              - List pages
GET /wp/v2/categories         - List categories
GET /wp/v2/tags               - List tags
GET /wp/v2/users              - List users
GET /wp/v2/media              - List media items
GET /wp/v2/{custom_post_type} - Custom post types
```

### Troubleshooting

**Connection fails:**
```bash
# Check REST API is enabled
curl https://your-site.local/wp-json

# Should return: {"name":"Site Name", ...}

# Check for firewall/security plugin blocking
# Disable firewall temporarily to test
```

**Authentication needed:**
```bash
# For protected endpoints, use application passwords
# WordPress Admin → Users → Your Profile → Application Passwords
# Generate a password, then add with auth:

claude mcp add --transport http wordpress https://your-site.local/wp-json \
  --auth "username:application-password"
```

## Exercise 2: WordPress Database Access via MCP (45 min)

**Task:** Set up direct MySQL database access for WordPress via MCP using dbhub.

**Context:** Sometimes you need direct database access for complex queries or bulk operations. MCP makes this safe and convenient.

### Requirements

1. Install dbhub MCP server
2. Connect to WordPress database
3. Run read-only queries on wp_posts
4. Query custom tables
5. Create a database reporting workflow

### Setup Steps

**Step 1: Install dbhub**

```bash
# Install dbhub MCP server (requires Node.js)
npm install -g @bytebase/dbhub
```

**Step 2: Get database credentials**

From your wp-config.php:

```php
define('DB_NAME', 'wordpress_db');
define('DB_USER', 'wp_user');
define('DB_PASSWORD', 'your_password');
define('DB_HOST', 'localhost');
```

**Step 3: Add database MCP server**

```bash
# Connect to WordPress database via MCP
claude mcp add --transport stdio db -- npx -y @bytebase/dbhub \
  --dsn "mysql://wp_user:your_password@localhost/wordpress_db"
```

**Step 4: Test with a query**

Ask Claude:

```
Can you show me the 10 most commented posts from the wp_posts table?
```

- ✅ Database MCP server connected

### WordPress Database Schema Reference

**Core WordPress tables:**

```sql
wp_posts          - Posts, pages, custom post types
wp_postmeta       - Post metadata (custom fields)
wp_users          - User accounts
wp_usermeta       - User metadata
wp_comments       - Comments
wp_terms          - Categories, tags, custom taxonomies
wp_term_taxonomy  - Taxonomy relationships
wp_term_relationships - Post-term relationships
wp_options        - Site settings
```

### Safe Query Practices

**✅ READ-ONLY is Best Practice:**

```sql
-- Safe: SELECT queries
SELECT post_title, post_date, comment_count
FROM wp_posts
WHERE post_status = 'publish'
ORDER BY comment_count DESC
LIMIT 10;

-- Safe: JOIN queries
SELECT p.post_title, pm.meta_value as featured
FROM wp_posts p
LEFT JOIN wp_postmeta pm ON p.ID = pm.post_id
WHERE pm.meta_key = 'featured_post';
```

**❌ AVOID Write Operations:**

```sql
-- Dangerous: Don't UPDATE directly
-- Use WordPress functions instead
UPDATE wp_posts SET post_status = 'draft' WHERE ID = 123;

-- Dangerous: Don't DELETE directly
DELETE FROM wp_posts WHERE post_date < '2020-01-01';
```

**💡 Best Practice:** Use read-only database credentials for MCP:

```bash
# Create read-only MySQL user
GRANT SELECT ON wordpress_db.* TO 'readonly_user'@'localhost'
IDENTIFIED BY 'secure_password';

# Use read-only user in MCP
claude mcp add --transport stdio db -- npx -y @bytebase/dbhub \
  --dsn "mysql://readonly_user:secure_password@localhost/wordpress_db"
```

### Safety Note

**IMPORTANT:** Use read-only database credentials to prevent accidental data modification. For write operations, always use WordPress functions (wp_insert_post, wp_update_post, etc.) to maintain data integrity.

### Implementation Steps

**Step 1: Choose Your Use Case**

For this exercise, let's build a **WordPress Health Check** MCP server.

**Step 2: Define MCP Server Functions**

Create `/claude-mcp-servers/wp-health-check.js`:

```javascript
#!/usr/bin/env node

// WordPress Health Check MCP Server
// Provides WordPress site health diagnostics

const readline = require('readline');

const tools = {
  'check-wordpress-version': {
    description: 'Check WordPress core version and compare to latest',
    handler: async () => {
      // Implementation: Query WordPress API and compare versions
      return {
        current: '6.7.1',
        latest: '6.7.1',
        status: 'up-to-date'
      };
    }
  },

  'check-plugin-updates': {
    description: 'List plugins needing updates',
    handler: async () => {
      // Implementation: Query plugins API
      return {
        needsUpdate: [
          { name: 'Contact Form 7', current: '5.8', latest: '5.9' },
          { name: 'Yoast SEO', current: '22.0', latest: '22.3' }
        ]
      };
    }
  },

  'check-security': {
    description: 'Run basic security checks',
    handler: async () => {
      // Implementation: Check for common security issues
      return {
        issues: [
          'Admin user with ID 1 exists',
          'File editing enabled in wp-config.php'
        ],
        passed: [
          'SSL certificate valid',
          'WordPress debug mode disabled'
        ]
      };
    }
  }
};

// MCP Server Implementation
async function main() {
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  console.log(JSON.stringify({
    jsonrpc: '2.0',
    method: 'tools/list',
    result: Object.keys(tools).map(name => ({
      name,
      description: tools[name].description
    }))
  }));
}

main();
```

**Step 3: Register MCP Server**

```bash
# Make script executable
chmod +x claude-mcp-servers/wp-health-check.js

# Add to Claude MCP configuration
claude mcp add --transport stdio wp-health \
  -- /path/to/claude-mcp-servers/wp-health-check.js
```

**Step 4: Test Your MCP Server**

Ask Claude:

```

"Check which plugins need updates"
"Run security diagnostics"
```

### Simplified Implementation

Don't want to build from scratch? Create a bash script wrapper:

```bash
#!/bin/bash
# wp-health-mcp.sh

case "$1" in
  "check-version")
    wp core version --allow-root
    ;;
  "check-plugins")
    wp plugin list --update=available --allow-root
    ;;
  "check-security")
    wp eval "echo wp_check_php_version();" --allow-root
    ;;
  *)
    echo "Unknown command: $1"
    ;;
esac
```

Then register it:

```bash
claude mcp add --transport stdio wp-health -- /path/to/wp-health-mcp.sh
```

## MCP Best Practices

### Security

✅ **DO:**
- Use read-only database credentials
- Authenticate API requests
- Validate all inputs
- Log access for audit trails

❌ **DON'T:**
- Expose production database with write access
- Store credentials in code
- Skip authentication checks
- Trust user input blindly

### Performance

✅ **DO:**
- Cache API responses when possible
- Use pagination for large datasets
- Implement rate limiting
- Optimize database queries

❌ **DON'T:**
- Fetch all data at once
- Make excessive API calls
- Run slow database queries
- Skip query optimization

### Maintenance

✅ **DO:**
- Document MCP server configurations
- Version your MCP servers
- Test after WordPress updates
- Share configurations with team

❌ **DON'T:**
- Leave undocumented servers running
- Forget to update access credentials
- Skip testing after changes
- Keep configuration knowledge siloed

## Troubleshooting MCP

### MCP Server Won't Connect

```bash
# Check MCP server is registered
claude mcp list

# Test connection manually
curl https://your-site.local/wp-json/wp/v2/posts

# Check Claude Code logs
claude logs

# Re-add MCP server
claude mcp remove wordpress
claude mcp add --transport http wordpress https://your-site.local/wp-json
```

### Database Queries Fail

```bash
# Test database connection
mysql -u wp_user -p wordpress_db -e "SELECT 1;"

# Check dbhub is installed
npm list -g @bytebase/dbhub

# Verify DSN format
# Correct: mysql://user:pass@host/database
# Wrong: mysql://host/database

# Re-add with correct credentials
claude mcp remove db
claude mcp add --transport stdio db -- npx -y @bytebase/dbhub \
  --dsn "mysql://correct_user:correct_pass@localhost/wordpress_db"
```

### MCP Server Timeouts

```bash
# Increase timeout in MCP config
# Edit ~/.claude/mcp-config.json
{
  "servers": {
    "wordpress": {
      "timeout": 30000  // 30 seconds
    }
  }
}

# Optimize slow queries
# Add database indexes if needed
```
