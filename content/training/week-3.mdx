## Exercise 2: Document & Refactor Legacy Code (45 min)

**File:** `exercises/week-3/exercise-2-legacy-code/blog-grid.php`

**Task:** Refactor a poorly-written theme file with deprecated functions and bad practices.

**Scenario:**
Open the file from your training repository. It contains 8 intentional bugs:

```php
<?php
query_posts('posts_per_page=-1&cat=5');
while (have_posts()) : the_post();
    echo '<div class="post">';
    echo '<h2>' . get_the_title() . '</h2>';
    echo '<p>' . $_POST['excerpt_length'] . '</p>';
    echo '<a href="' . get_permalink() . '">Read more</a>';
    echo '</div>';
endwhile;
wp_reset_query();
?>
```

**Requirements:**
- Replace deprecated `query_posts()` with `WP_Query`
- Fix the security vulnerability (`$_POST` without sanitization)
- Add proper escaping to all output
- Remove the unlimited posts query (`-1`)
- Add pagination
- Make the category configurable
- Document what each fix addresses

**Success Criteria:**
- ✅ No deprecated functions used
- ✅ All output properly escaped
- ✅ No security vulnerabilities
- ✅ Posts limited to reasonable number
- ✅ Code follows WordPress coding standards
- ✅ All changes documented

**Skills Practiced:**
- Identifying WordPress anti-patterns
- Security awareness (sanitization, escaping)
- Proper query usage
- Code refactoring with Claude

**What's Wrong:**
- `query_posts()` is deprecated and breaks main query
- `posts_per_page=-1` loads ALL posts (performance issue)
- `$_POST` used directly without sanitization (security issue)
- `get_the_title()` not escaped (XSS vulnerability)
- `get_permalink()` not escaped
- Hardcoded category ID

  - Missing capability checks
  - Unsanitized input
- Test each fix
- Document the security principles

**Success Criteria:**
- ✅ `/security-audit` command runs successfully
- ✅ All identified vulnerabilities fixed
- ✅ Nonce verification added to form handler
- ✅ Capability check prevents unauthorized access
- ✅ All inputs sanitized (text, URLs, numbers)
- ✅ All outputs escaped
- ✅ Security principles documented

**Skills Practiced:**
- Using `/security-audit` skill
- WordPress security functions
- CSRF protection with nonces
- Input sanitization
- Output escaping
- Capability checks

**Key Security Functions to Use:**
```php
// Nonce verification
wp_verify_nonce($_POST['_wpnonce'], 'my_action');

// Capability check
current_user_can('manage_options');

// Input sanitization
sanitize_text_field($_POST['field']);
sanitize_url($_POST['url']);
absint($_POST['number']);

// Output escaping
esc_html($text);
esc_url($url);
esc_attr($attribute);
```

## WordPress Security Checklist

Use this checklist when reviewing code (with or without Claude):

### Input Validation
- [ ] All `$_POST` / `$_GET` / `$_REQUEST` data sanitized
- [ ] File uploads validated (type, size, extension)
- [ ] URLs validated with `esc_url_raw()`
- [ ] Numbers cast with `absint()` or `intval()`

### Output Escaping
- [ ] All echoed text uses `esc_html()`
- [ ] All URLs use `esc_url()`
- [ ] All attributes use `esc_attr()`
- [ ] Database queries use `$wpdb->prepare()`

### Authorization
- [ ] Nonce verification on all form submissions
- [ ] Capability checks before sensitive actions
- [ ] AJAX requests verify nonces
- [ ] Admin pages check `current_user_can()`

### Common Vulnerabilities
- [ ] No SQL injection (use `$wpdb->prepare()`)
- [ ] No XSS (escape all output)
- [ ] No CSRF (use nonces)
- [ ] No unauthorized file access
- [ ] No direct database queries without sanitization

---

## Anti-Patterns to Avoid

### ❌ DON'T USE
- `query_posts()` - Use `WP_Query` or `get_posts()`
- `$_POST` directly - Always sanitize first
- `echo` without escaping - Use `esc_html()`, `esc_url()`, etc.
- `posts_per_page=-1` - Limit queries for performance
- `@` error suppression - Fix the underlying issue
- `eval()` - Never use, major security risk

### ✅ DO USE
- `WP_Query` for custom queries
- `sanitize_*()` for all inputs
- `esc_*()` for all outputs
- Reasonable query limits
- Proper error handling
- WordPress functions over PHP equivalents
