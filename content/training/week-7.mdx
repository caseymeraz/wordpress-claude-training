## Exercise 1: WordPress 7.0 Compatibility Audit (45 min)

**Task:** Audit your WordPress codebase for deprecated functions and prepare for WordPress 7.0.

**Context:** WordPress 7.0 deprecates several functions. Use Claude to scan your project and create a compatibility report.

### Requirements

1. Scan entire WordPress project for deprecated functions
2. Generate compatibility report with findings
3. Fix at least 3 deprecated function calls
4. Document the replacements used
5. Create a "WordPress 7.0 Readiness Checklist"

### Deprecated Functions to Check

- `query_posts()` → Use `WP_Query`
- `wp_get_http()` → Use `wp_remote_get()`
- `wp_specialchars()` → Use `esc_html()`
- `screen_icon()` → Removed, use CSS
- `get_bloginfo('text_direction')` → Use `is_rtl()`

### Success Criteria

- ✅ Claude scans entire project and generates report
- ✅ All deprecated functions identified with line numbers
- ✅ At least 3 functions replaced with modern equivalents
- ✅ Compatibility checklist created
- ✅ No errors after running updated code

### Skills Practiced

- Code auditing with Claude
- WordPress version compatibility
- Modern WordPress API usage
- Documentation of technical debt

### Example Prompt

```
Scan this WordPress project for functions deprecated in WordPress 7.0.
Generate a report with:
1. Each deprecated function found
2. File path and line number
3. Recommended modern replacement
4. Priority (critical/medium/low)

Then help me fix the critical issues.
```

### Common Deprecated Functions

**Already Deprecated (Fix Now):**
```php
// ❌ Don't use
query_posts('showposts=10');

// ✅ Use instead
$query = new WP_Query(array('posts_per_page' => 10));
```

```php
// ❌ Don't use
wp_specialchars($text);

// ✅ Use instead
esc_html($text);
```

**WordPress 7.0 Deprecations (Prepare For):**
```php
// ❌ Will be deprecated
get_page_by_title('About Us');

// ✅ Use instead
get_posts(array(
    'title' => 'About Us',
    'post_type' => 'page',
    'numberposts' => 1
));
```

## Exercise 2: Classic Theme to Block Theme Conversion (60 min)

**Task:** Convert a classic PHP template to a modern block theme using FSE patterns.

**Context:** Block themes are mandatory in WordPress 7.0. Learn to convert traditional PHP templates to block-based patterns.

### Requirements

1. Take a classic theme template (header.php, footer.php, single.php)
2. Convert to FSE block patterns
3. Generate theme.json configuration
4. Test the converted template in Block Editor
5. Ensure all functionality preserved

### Part 1: Convert Header Template (20 min)

**Starting Point:** Classic header.php

```php
<!DOCTYPE html>
<html <?php language_attributes(); ?>>
<head>
    <meta charset="<?php bloginfo('charset'); ?>">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <?php wp_head(); ?>
</head>
<body <?php body_class(); ?>>
<?php wp_body_open(); ?>
<header class="site-header">
    <div class="container">
        <div class="site-branding">
            <?php the_custom_logo(); ?>
            <h1><?php bloginfo('name'); ?></h1>
        </div>
        <nav class="main-navigation">
            <?php
            wp_nav_menu(array(
                'theme_location' => 'primary',
                'menu_class'     => 'primary-menu',
            ));
            ?>
        </nav>
    </div>
</header>
```

**Goal:** Convert to block pattern in `/patterns/header.php`

### Part 2: Create theme.json (15 min)

**Required Settings:**
- Color palette (at least 5 colors)
- Typography (font families and sizes)
- Spacing scale
- Layout settings

### Part 3: Test in FSE (10 min)

- Load template in Site Editor
- Verify all blocks editable
- Test responsive behavior
- Ensure no functionality lost

### Part 4: Convert Additional Templates (15 min)

Choose one to convert:
- Footer template
- Single post template
- Archive template

### Success Criteria

- ✅ Classic templates converted to block patterns
- ✅ theme.json generated with correct settings
- ✅ All original functionality works
- ✅ Editable in Full Site Editor
- ✅ No PHP template fallbacks needed

### Skills Practiced

- FSE architecture understanding
- Block pattern creation
- theme.json configuration
- Template hierarchy in block themes

### Example Prompt

```
I have this classic header.php template. Convert it to a block theme pattern:

[paste header.php code]

Requirements:
- Maintain all functionality (logo, menu, search)
- Use core WordPress blocks where possible
- Make it editable in FSE
- Generate the corresponding theme.json settings
```

### Block Pattern Example

Here's what the converted header might look like:

```php
<!-- wp:group {"tagName":"header","className":"site-header"} -->
<header class="wp-block-group site-header">
    <!-- wp:group {"className":"container"} -->
    <div class="wp-block-group container">
        <!-- wp:group {"className":"site-branding"} -->
        <div class="wp-block-group site-branding">
            <!-- wp:site-logo /-->
            <!-- wp:site-title /-->
        </div>
        <!-- /wp:group -->

        <!-- wp:navigation {"overlayMenu":"mobile"} /-->
    </div>
    <!-- /wp:group -->
</header>
<!-- /wp:group -->
```

## Common FSE Mistakes to Avoid

### ❌ DON'T

1. **Don't mix classic and block templates**
   - Decide on one approach and stick with it
   - Use either PHP templates OR block templates, not both

2. **Don't skip theme.json**
   - It's required for block themes
   - Controls all global styles

3. **Don't hardcode styles in patterns**
   - Use theme.json settings instead
   - Makes styles editable in Site Editor

4. **Don't forget responsive testing**
   - FSE makes it easy to break mobile
   - Test all templates on small screens

### ✅ DO

1. **Use core blocks when possible**
   - Leverage existing WordPress blocks
   - Only create custom blocks when truly needed

2. **Organize patterns by purpose**
   - Create reusable patterns
   - Name them clearly (header, footer, hero, etc.)

3. **Test in Site Editor frequently**
   - Verify blocks are editable
   - Check that changes persist

4. **Document your block patterns**
   - Add pattern descriptions
   - Include usage examples

## Troubleshooting FSE Issues

### Templates Not Showing in Site Editor

**Problem:** Your block templates don't appear in the Site Editor.

**Solutions:**
```bash
# Check template file naming
# Must be in /templates/ directory
# Must use .html extension
# Example: /templates/index.html

# Verify theme.json exists
ls theme.json

# Check theme.json is valid JSON
cat theme.json | python -m json.tool
```

### Blocks Not Editable

**Problem:** Block patterns show but can't be edited in Site Editor.

**Solutions:**
```php
<!-- Ensure blocks use proper structure -->
<!-- wp:group {"className":"my-class"} -->
<div class="wp-block-group my-class">
    <!-- Content here -->
</div>
<!-- /wp:group -->

<!-- Not this: -->
<div class="my-class">
    <!-- This won't be editable -->
</div>
```

### Styles Not Applying

**Problem:** theme.json styles don't show up.

**Solutions:**
```json
{
  "version": 2,  // Must be version 2
  "settings": {
    "color": {
      "palette": [
        // Use exact structure
        {
          "name": "Primary",
          "slug": "primary",  // No spaces, lowercase
          "color": "#007bff"
        }
      ]
    }
  }
}
```
